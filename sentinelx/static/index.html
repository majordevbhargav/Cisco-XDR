Evaluating Context Integration for Network Anomaly Detection

This sandbox tests the core hypothesis of your NAIST research proposal: adding device identity, VLAN segments, and historical familiarity to standard traffic metrics improves anomaly interpretation and reduces administrator alert fatigue.

Phase 1

Traffic-Only Baseline

Evaluates flows strictly using packet size, flow duration, byte counts, and connection rate. Utilizes an Isolation Forest unsupervised model.

Misses stealthy, low-volume attacks (R2L, device compromise). High false positives for normal data bursts.
Phase 2

Context-Aware Detection

Integrates Cisco ISE inspired details: device roles, network segments, destination familiarity, and historical deviations.

Exposes stealthy Remote-to-Local attacks by identifying access-policy violations. Dampens baseline false alarms.
Phase 3

Risk-Informed Operations

Applies an interpretable scoring formula combining traffic anomalies, context deviations, destination reputation, and asset criticality values.

Prioritizes alerts into actionable tiers (Low, Medium, High, Critical). Drastically reduces raw alert volume.
